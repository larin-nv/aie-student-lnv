## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` — зависимости для локальной разработки.
- `requirements-prod.txt` — минимальный набор зависимостей для Docker-образа.
- `report.md` — полный отчёт по проекту (постановка задачи, данные, эксперименты, архитектура, наблюдаемость).
- `Dockerfile` — контейнеризация сервиса для воспроизводимого развёртывания.
- `.dockerignore` — исключение лишних файлов из Docker-образа.
- `.gitignore` — исключение виртуального окружения, секретов, кэша, сырых данных.
- `notebooks/` — экспериментальные ноутбуки:
  - `exp01_eda.ipynb` — разведочный анализ данных;
  - `exp02_modeling_and_evaluation.ipynb` — обучение и сравнение моделей.
- `src/` — основной код проекта:
  - `src/data/prepare_data.py` — пайплайн предобработки и генерации признаков;
  - `src/service/main.py` — FastAPI-сервис с эндпоинтами `/health` и `/predict`.
- `data/` — данные:
  - `data/raw/employee_burnout_raw.csv` — исходный датасет (в `.gitignore`, не коммитится);
  - `data/processed/employee_burnout_processed.csv` — обработанные данные;
  - `data/processed/burnout_sample.csv` — демо-выборка (100 строк).
- `configs/` — конфигурационные файлы:
  - `.env.example` — пример переменных окружения (порт, хост, уровень логирования).
  - `configs/config.yaml` — пути к артефактам, гиперпараметры модели, параметры логирования.
- `tests/` — тесты:
  - `tests/test_api.py` — тесты API-сервиса (5 тестов);
  - `tests/test_data.py` — тесты предобработки данных (3 теста).
- `artifacts/` — сохранённые артефакты:
  - `artifacts/model.pkl` — обученная модель CatBoost;
  - `artifacts/feature_columns.pkl` — список признаков для валидации;
  - `artifacts/class_distribution.png` — графики распределения классов из EDA.
  - `artifacts/correlation_matrix.png` — корреляционная матрица признаков из EDA.
  - `artifacts/boxplots.png` — boxplot-диаграммы из EDA.
  - `artifacts/categorical.png` — диаграмма распределения категориальных признаков по классам из EDA.
  - `artifacts/mean_difference.png` — диаграмма разницы средних значений из EDA.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.12`
- Docker (для контейнеризованного запуска)
- Установленные системные зависимости: `git`

### 3.2. Установка окружения

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение (опционально, но рекомендуется)
python -m venv .venv

# Активировать окружение:
# Windows:
.\.venv\Scripts\Activate.ps1
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Как запустить проект

### 4.1. Запуск подготовки данных

```bash
cd project
.\.venv\Scripts\Activate.ps1
python -m src.data.prepare_data
```

### 4.2. Запуск обучения модели

Открыть ноутбук `notebooks/exp02_modeling_and_evaluation.ipynb` и выполнить все ячейки.
Модель и список признаков будут сохранены в `artifacts/`.

### 4.3. Запуск сервиса (API/веб-интерфейс)

```bash
cd project
.\.venv\Scripts\Activate.ps1
python -m src.service.main
```

Или, если используется Docker:

```bash
cd project
docker build -t aie-project .
docker run -p 8000:8000 aie-project
```

- Сервис поднимается на порту `8000`
- Эндпоинты: GET /health - проверка работоспособности сервиса; POST /predict - получение предсказания риска выгорания
- Протестировать можно через запрос `curl`:
```bash
curl -X 'POST' \
  'http://localhost:8000/predict' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "gender": 0,
  "company_type": 0,
  "wfh_setup_available": 0,
  "designation": 2,
  "resource_allocation": 3,
  "mental_fatigue_score": 3,
  "tenure_months": 12,
  "fatigue_resource_ratio": 1,
  "is_senior": 0,
  "high_workload": 0
}'
```
Пример ответа:
```json
{
  "burnout_probability": 0.003,
  "risk_level": "LOW",
  "top_factors": [
    {
      "feature": "mental_fatigue_score",
      "importance": 48.58,
      "value": 3
    },
    {
      "feature": "resource_allocation",
      "importance": 21.34,
      "value": 3
    },
    {
      "feature": "wfh_setup_available",
      "importance": 8.62,
      "value": 0
    }
  ]
}
```

## 8. Ограничения и дальнейшая работа

Текущие ограничения:

1. Модель обучена на открытом синтетическом датасете; реальные корпоративные данные могут иметь иное распределение и скрытые смещения.
2. Отсутствует учёт временной динамики — модель анализирует срез данных без отслеживания изменений состояния сотрудника.
3. Не реализованы механизмы аутентификации API (JWT/OAuth) и rate limiting.
4. Отсутствует автоматический мониторинг дрейфа данных (data drift) в реальном времени.

Направления дальнейшей работы:

1. Интеграция с HR-экосистемой: боты для Slack/MS Teams, дашборды для визуализации уровня выгорания по отделам.
2. Расширение признаков: NLP-анализ текстовых отзывов сотрудников, учёт временных рядов.
3. MLOps и безопасность: внедрение пайплайна непрерывного обучения (MLflow, DVC), авторизация API, мониторинг дрейфа данных (Evidently AI).
4. A/B тестирование: оценка эффективности рекомендаций по снижению выгорания.
